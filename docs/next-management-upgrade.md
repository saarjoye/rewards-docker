# Next 管理台优化验收记录

## 数据口径

运行执行、账号执行和积分确认分别表达。余额观测仅接收带明确时区、可靠来源和有效数值的证据；不将任务完成或进度变化直接换算成积分到账。

当前适配器没有提供独立任务积分证据，因此上报、确认及待确认积分值保持未知。任务执行完成可以与积分待确认同时存在。页面不从余额残差推测任务来源。

单次运行余额使用该运行的可靠起点和最新观测；中断缺少结束观测时本轮保持待确认。当日变化仅使用上海同一业务日期内的观测，保留零和负数。跨午夜在原运行内重新发现次日任务，旧日请求保留原身份；没有午夜边界观测时不推算每日缺口。

## 数据库兼容

后续任务证据采集新增 Schema 3 `task_evidence`：保存任务执行状态、提交回执、复核进度和 App 响应余额的白名单字段。重复观测按内容哈希幂等写入，与余额账本使用同一保存点提交。签到、App 活动和分次阅读复用已有响应，不增加 Rewards 请求。任务证据通过运行详情账号的 `taskEvidence` 返回；不存原始响应或认证材料，不改写历史积分。

这些记录是观测证据，不是官方积分流水。不同运行的执行证据独立保留，不作为积分累加项；没有官方到账身份时 `creditKey` 和 `confirmedPoints` 保持空值。尚未实现官方到账事件解析、独立的任务前余额采样或新的延迟到账查询。运行详情现已按任务展示逐条证据，支持执行记录、提交回执和任务复核筛选；进度、观测余额和到账证据分别呈现，不将回执成功或任务完成当作到账。

Schema 2 新增 `run_tasks`、`balance_observations`、`account_lifecycle`，在事务中幂等创建，不回填旧积分或删除历史。旧任务当前状态继续保留；新运行报告使用独立运行快照。

旧历史没有任务快照时显示明细尚未取得，没有可靠余额证据时保持待确认。旧管理会话如果不支持恢复，需要重新登录一次，账号与任务数据不受影响。

生产部署前必须另行授权一致性备份与迁移。回退版本时保留新增表，不删除数据库或 WAL。此次没有部署或接触生产数据库。

## 接口与页面

- `GET /api/session` 恢复现有管理会话，响应禁止缓存；认证材料不进入浏览器持久存储。
- `GET /api/state?date=YYYY-MM-DD` 支持任务日期筛选，当前日期与余额观测单独返回。
- `GET /api/runs?page=1&pageSize=20` 分页；`GET /api/runs/:runId` 按 ID 查询，不限制最近一百次。
- `GET /api/calendar?month=YYYY-MM` 与详情共用余额统计；报告只读取该运行的快照。
- 页面新增历史详情、月日历、账号改名、任务筛选、处理状态与时间范围；刷新请求合并并丢弃过时响应。
- 详情轮询、运行结束和失败恢复保留已展开任务与筛选。不同运行切换不显示前一个运行的旧数据；未知运行显示明确错误并可返回。日历来源显示“返回日历”，历史来源显示“返回记录”。
- 时间按上海时区展示“开始时间—结束时间＝执行时长”；无结束时间且仍执行时显示“进行中”，非法或倒序区间保持未知。窄屏证据表按记录纵向排列，顶栏按钮不竖排，平板优先显示工作内容。

## 验证与限制

受控 App 单次入口为既有验收脚本的 `--single-app-submission` 显式开关，默认仍只读。仅选择受支持且未完成的 App 活动或有旧日观测依据的签到；无候选就停止。发送前以账号身份摘要与上海日期原子创建持久保留标记，不自动重试或删除该标记。该门禁只保护验收脚本，不替代生产任务账本，也不能阻止其他设备同时执行。受控响应只检查白名单结构，不代表到账确认。前一阶段经明确授权执行后因无合格候选退出，没有发送真实任务；本轮页面验收不执行该脚本。

2026-09-08 经授权完成单账号直连 App 只读结构核查。解析前白名单范围发现 balance、offerid、complete、progress、max、pointprogress、pointmax；未发现所检查的候选到账金额或流水 ID 字段。检查未截断，但存在未检查分支，不构成对完整响应或其他接口的否定结论。结构摘要只含固定字段名、类型和次数，不保存原始响应或字段值。真实任务提交响应不在此次只读核查范围内。

离线验收覆盖余额零值、负值、缺失证据、迁移回滚、重复迁移、快照隔离、重启恢复、跨日发现与搜索提交保护、会话恢复、旧记录直接查询和请求合并。
