# 运行状态、通知与积分证据

## 账号结束与运行结束

单容器的实际源码在 `src/`，Fastify 与运行编排使用同一个 SQLite 账本，不再通过旧版 Core 日志轮询传递完成信息。

`RunLedger.lifecycle` 在账号结束时保存结构化 `ACCOUNT-END`：运行与账号标识、脱敏标签、执行结果、起止时间、时长、可靠余额及完成键。生命周期、完成事件和已启用的账号通知入队在同一事务提交。`account-complete:{runId}:{accountId}` 与 `account:{runId}:{accountId}` 分别用于事件与通知去重。正式运行尚未入库也可以发送账号通知。

已结束账号不会被普通后续失败或整轮中断降级；明确完成证据可以补充此前未完成状态。SIGTERM/SIGINT 调用等待式停止，整轮记录为 interrupted；此前已完成账号保持 completed，未开始账号保持 queued。执行完成与积分确认是两种状态。

## 推送设置与队列

“消息推送”提供企业微信应用配置、保存、测试和最近队列状态。沿用现有主密钥加密设置；不回显应用 Secret，编辑时留空保留已保存值。接口沿用登录与防跨站请求校验。不会读取旧双容器配置，也不会默认打开推送。

企业微信反代地址是可选的 `apiBaseUrl`。留空使用官方接口，支持 HTTPS 域名及路径前缀；末尾 `/cgi-bin/` 会规范化，获取令牌和发送消息均在同一个基础地址下追加官方路径。拒绝 HTTP、IP 字面量、本地专用域名、URL 鉴权信息、查询参数及片段，不跟随重定向。地址必须是管理员信任并控制的服务，因为企业微信应用凭证和消息会经过它；这不是 Rewards 的网络代理，也不修改系统代理。域名的实际解析及反代服务器安全由部署者管理。

读取设置返回规范化地址；保存时省略该字段保留现有反代，显式留空切回官方接口。更改地址会清空内存令牌缓存，保持通知队列及收件人规则。新增可空列 `notification_settings.api_base_encrypted`，在既有启动事务中幂等添加，只保存加密地址，旧记录默认官方地址。旧版加密设置 JSON 结构不变，回退旧应用时该列被忽略且使用官方接口；回退不会继续使用反代。不要删除数据库或密钥进行回退。本轮只在合成数据库测试，未填写真实地址或发送真实消息。

启用后新产生的账号结束事件立即入队，状态订阅立即尝试发送；每秒扫描补偿重启和发送期间新增任务。整体终态独立生成 `run:{runId}` 汇总，正常结束、中断、失败或主动停止都不会撤销账号通知。启用前已经结束的历史不补发，启用前开始但启用后结束的运行可以通知。

队列持久保存类型、运行、账号、创建时间、发送次数、下次尝试时间、安全失败码及接口接受时间。流程为 pending → sending → sent；失败退避从 30 秒开始翻倍，最多一小时，最多尝试次数可配置为 1–8（默认 5）。耗尽保留 failed，不删除。sending 使用 60 秒租约，重启后过期任务恢复。更换收件目标取消旧未发送任务；关闭开关暂停发送。成功只表示企业微信接口接受，最终客户端投递未知。

队列提供至少一次投递。企业微信重复检查窗口为 30 分钟；如果外部接口已接受但本地来不及写 sent 就崩溃，无法保证绝对不重发。单容器单进程是当前支持范围。重试耗尽记录目前需要诊断处理，没有自动无限重试。

## 两套账本与统一统计

`balance_observations` 保存实际读取到的余额、来源、观测时间、上海业务日期及 start/task-before/task-after/end 阶段。复用现有请求结果；没有新的 Rewards 轮询。缓存余额作为任务边界证据时保留原观测时间，不伪装成刚刚读取。

`point_credits` 保存任务上报、预计值、稳定身份、证据类型、快照引用和确认结果。稳定键以账号及来源为范围：官方事件 ID 优先，否则使用稳定任务实例、上海业务日期和信用类型。键不包含运行 ID，首次运行归属不被重试移动。同键重复只保留一份；冲突金额不自动选择或平摊。无稳定身份的旧记录保留 legacyUnverified，不能确认。

确认只接受官方唯一到账事件，或有稳定任务身份、可靠前后余额、明确隔离证据且无重叠窗口的余额归因。仅任务进度、预计积分、执行完成或请求成功不能确认。确认事件还必须落在对应余额观测区间内。App activity 和 RSC action 已接通严格的可选到账回执传递：仅识别同一对象中匹配任务的 `offerId`、明确的 `officialCreditId` 和非负整数 `earnedPoints`。不使用普通 request ID、amount 或任务进度替代。该结构只用合成数据验证，尚未证实当前线上 Rewards 会返回这组字段，不能宣称已取得生产官方流水或已支持全部任务精确归因。

任务复核保存 `official-progress`，明确的 `pointProgressMax`/`pointmax` 可保存为预计积分，仍保持积分 pending；普通活动次数上限不换算成积分。执行记录本身不再创建三种金额全为空的积分占位；实际提交而无积分值时仍保留 task-report/pending，未知金额不转换为零。DOM 顺序生成的任务身份标记不稳定，不用于确认积分。余额缓存沿用实际观测时间，不自动产生隔离证明。运行详情证据面板读取关联积分账本，不再硬编码“未取得到账证据”。

## 账号结果与活动链接修复（next.4）

账号结束状态以最终任务汇总结果映射：success → completed，partial → partial，其他终态原样保留。账号已结束后，普通历史 upsert 不覆盖其结果；success 仅代表 completed。账号结束消息按完成、部分完成、失败、需人工处理、取消或中断分别生成标题，并记录阶段、安全原因、已完成任务数、未确认任务数及余额确认情况。账号通知与运行通知的事务、键及退避规则不变。

活动链接仅匹配无 URL 鉴权的 HTTPS：规范化主机、默认端口和尾斜杠，只忽略明确追踪参数，保留业务参数和 Bing q/filters。备用匹配要求可信 Rewards 页面包装链接、匹配的 destination 及唯一的任务 ID/offer ID/aria-label/title；不使用标题绕过不同搜索词或不同 filters。隐藏链接不参与匹配，有歧义时不点击。最多两轮重新读取 earn、dashboard 和 Bing flyout；日志仅记录候选数和匹配结果，不记录 URL、页面文本或账号。未点击而确实找不到链接属于可解释的 verification-pending，不清除已提交的 mutation，不冒充任务完成。

任务阶段失败且已取得有效发现上下文时，进行一次额外只读余额收口；失败不伪造 end 快照。取消、人工处理及未完成认证不进入此补偿。仅同账号、同运行、可靠起止时间且无冲突的余额可确认。5804 → 5804 为 0，缺少结束余额为 null。跨日按原有上海日期分账。未重写旧历史，既有错误 completed 和空积分占位不会自动修成新值。

本修复不新增 schema 或迁移版本：现有 execution_state 为 TEXT，已支持 partial；结束事件 JSON 只增加诊断字段，旧事件缺少字段时显示未取得。兼容测试直接构造旧积分行并重复迁移，核对旧值保留。

统一 `RunViews` / `PointCredits` 服务供首页、任务页、详情、日历、报告和通知使用：

| 字段 | 含义 |
| --- | --- |
| reportedTaskPoints | 任务报告积分，缺失保持 null |
| confirmedTaskPoints | 有稳定身份和可靠证据的确认积分；超出余额证据或冲突保持 null |
| pendingTaskPoints | 已提交未确认任务的预计积分；未知预计值保持 null |
| runBalanceDelta | 同账号同运行起点到可靠终点的差；仅当前活跃账号允许暂时余额 |
| dailyBalanceDelta | 同账号同上海日期最早与最后可靠观测差 |
| unattributedBalanceDelta | 正余额中无法关联唯一任务证据的残差，不生成来源 |
| overreportedTaskPoints | 上报超出可靠正余额变化的部分 |

205 余额变化、120 严格确认任务积分得到 85 残差；111 上报、83 余额得到 28 超额，不显示成残差。缺失、冲突、旧 account-balance 混入或上报超额时不伪造唯一归因。负余额保留负数。任务确认总额冲突时不任意挑选任务凑余额。

当日统计不会跨上海午夜补齐缺口；本轮可跨日并按日提供详情。中断缺少结束快照时本轮保持未知，当日已观测余额可标记暂时。临时和正式结果按相同运行与账号重算替换，不相加。

生命周期、任务、余额或信用事件均可生成临时详情与日历记录。SSE 只发送失效提示，不传认证或原始数据；页面合并刷新，重连重读完整状态，失败保留旧观测并显示过期。

## 迁移与验证

运行账本 schema v4 在事务内新增 `account_completions`、`point_credits` 和完成来源字段；通知 schema v2 幂等创建加密设置、队列及入队触发器。启动重复迁移不增加积分、不删除旧数据，失败回滚。本轮只在临时 SQLite 验证，未迁移生产数据。

离线检查：`npm run check`、`npm run lint`、`npm test -- --reporter=dot`。隔离构建后用 `node scripts/ui-acceptance.mjs` 验收四种屏宽、详情跳转、重载、事件更新和模拟推送。镜像由既有 Actions 双架构构建，禁网空数据健康检查通过后才更新版本与 latest。
