# Git

- 新目录未获得明确授权前不得初始化 Git；初始化、首次提交和远程操作分别授权。
- 不使用 `git add .`、`git add -A`、强推、历史改写、`reset --hard` 或 `clean -fd`。
- 每项完整任务最多一个提交，只暂存明确文件，提交前运行测试、构建、`git diff --check` 和敏感扫描。
- `.env`、`data/`、`sessions/`、`secrets/`、日志、备份、诊断包和 `.codex-notes/` 永不提交。
- 远程地址、分支和提交范围必须在联网前展示并再次确认。
## D:\开发 统一任务流程

本节适用于 `D:\开发` 下的项目任务；如本文前文存在旧的授权表述，以本节和上级 `D:\开发\AGENTS.md` 为准。

- 任务开始只读查询仓库根、当前分支、`git status --short --branch`、最近提交、已跟踪文件和 remote 元数据；不连接 remote。
- 没有 `.git` 且实际源码项目边界明确时，只在项目根目录初始化，新仓库默认分支为 `main`；初始化前检查 `.gitignore`、敏感文件和大文件。若 `.git` 已存在但为空、损坏或状态异常，不删除或重建，先报告并暂停。集合目录、缓存目录或项目规则明确指定嵌套源码仓库时，优先使用指定仓库。
- 已有未提交改动时，先对安全且明确属于基线的文件建立基线提交；无法安全区分的文件保留并报告。
- 任务完成并通过适用验证后，一项完整任务自动生成一个本地中文提交；只读任务或没有安全文件变更时不提交。
- 只暂存明确属于基线或本次任务的具体文件，禁止批量暂存、破坏性恢复、覆盖用户文件和绕过 hooks。
- `.env*`、凭证、密钥、证书、数据库、日志、导出、备份、缓存、依赖、构建产物、临时文件和大文件默认不提交；检查失败时不创建最终任务提交。
- 不自动添加 remote、fetch、pull、push、创建 PR 或修改 remote。
